# 요구사항정의서 (Software Requirements Specification)

**프로젝트:** Linker — 하나카드 AI 상담 에이전트
**대상 시스템:** 음성·텍스트 기반 고객상담 챗봇 + 상담사 이관/대시보드
**문서 버전:** 1.0 (2026-07-03)
**작성 근거:** 현행 코드베이스 실측 분석 (`hana-linker/`)

> 본 문서는 *현재 구현된 서비스*를 기준으로 역공학하여 정리한 요구사항정의서다. 각 요구사항은 실제 코드/설정에 매핑되며, 향후 개선 항목은 `docs/REQUIRED_IMPROVEMENTS.md`, 비용/용량은 `docs/COST_ESTIMATION.md`를 참조한다.

---

## 1. 문서 개요

### 1.1 목적
하나카드 고객센터의 1차 상담을 자동화하고, AI가 처리할 수 없는 문의를 상담사에게 **맥락과 함께 이관**하는 대화형 에이전트의 기능·비기능 요구사항을 정의한다.

### 1.2 범위
- 포함: 고객 음성/텍스트 상담, 의도분류, RAG 기반 자동응답, 슬롯 기반 정보수집, 상담사 이관, 요약·감성분석·문서추천, 상담사 대시보드, 세션/대화 영속화.
- 제외: 실제 상담사 인력 운영(WFM), 카드사 코어뱅킹 연동, 결제/인증 실거래 처리.

### 1.3 용어
| 용어 | 정의 |
|---|---|
| Triage | 고객 발화를 4개 티켓(SIMPLE/AUTO/NEED_MORE_INFO/HUMAN_REQUIRED)으로 분류 |
| 슬롯(Slot) | 상담사 이관 전 수집하는 구조화 정보 항목(예: 카드 뒤 4자리) |
| 핸드오버(Handover) | AI→상담사 이관. `pending → accepted/declined/timeout` 상태를 가짐 |
| 턴(Turn) | 유저 1발화 + 봇 1응답 = 1왕복 |
| KMS | 상담사에게 추천되는 지식/문서(Knowledge Management System) |

### 1.4 참고 문서
`CLAUDE.md`, `docs/COST_ESTIMATION.md`, `docs/analysis/ARCHITECTURE_ANALYSIS.md`, `e2e_evaluation_pipeline/configs/kpi_thresholds.py`

## 2. 시스템 개요

### 2.1 구성
```
[고객 음성챗봇 :3010]   [상담사 대시보드 :3000]
        │  (REST /api/v1 · WebSocket, /api 프록시)
        ▼
[FastAPI 백엔드 :8000] ── LangGraph 워크플로우(ai_engine/graph/workflow.py)
   ├ 음성: STT(VITO) · TTS(Google) · VAD(Silero/WebRTC)
   ├ 지식: ChromaDB(Hybrid 검색 + Reranker)
   ├ LLM: Ollama/OpenAI 호환(qwen3.5:9b) · 의도분류(KcELECTRA+LoRA, 38종)
   └ 영속: MySQL(chat_sessions, chat_messages)
```

### 2.2 사용자(액터)
| 액터 | 설명 |
|---|---|
| 고객 | 음성/텍스트로 상담. 카드/금융 문의, 상담사 연결 요청 |
| 상담사 | 대시보드에서 이관 세션 수락, 요약·감성·추천문서 확인, 고객 응대 |
| 시스템 운영자 | 배포·모니터링·지식베이스 인덱싱 |

### 2.3 대화 흐름(2-플로우)
- **일반 플로우** (`is_human_required_flow=False`): `triage_agent → answer_agent → chat_db_storage → END`
- **핸드오버 플로우** (`is_human_required_flow=True`): 진입 라우터 → `consent_check → waiting_agent → chat_db_storage`, 수집 완료 시 → `summary_agent → human_transfer → END`

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 대화 오케스트레이션
| ID | 요구사항 | 근거 |
|---|---|---|
| FR-ORC-01 | 시스템은 세션별 대화 이력을 재적재하여 멀티턴 상태(플로우 플래그, 수집정보)를 유지해야 한다. | `workflow_service`, `GraphState` |
| FR-ORC-02 | 진입 라우터는 `is_human_required_flow`, `customer_consent_received`, `out_of_domain_count`, `unclear_count`로 다음 노드를 결정해야 한다. | `_entry_router` |
| FR-ORC-03 | 입력 검증 계층은 2자 미만·2000자 초과 발화를 그래프 실행 전에 거부해야 한다. | `workflow_service` (External Validation) |
| FR-ORC-04 | 대화 턴은 하드 상한(설계상 5턴)을 가지며, 불명확/도메인외 응답이 3회 누적되면 세션을 종료해야 한다. | `unclear_count`, `out_of_domain_count` |

### 3.2 의도분류 (Intent Classification)
| ID | 요구사항 | 근거 |
|---|---|---|
| FR-INT-01 | 고객 발화를 38개 카테고리(9개 도메인)로 분류하고 top-3와 신뢰도를 제공해야 한다. | KcELECTRA+LoRA, `intent_classification_tool` |
| FR-INT-02 | 분류 결과는 후속 슬롯 카테고리 결정과 triage 판단의 보조 근거로 사용되어야 한다. | `context_intent` |

### 3.3 Triage (티켓 분류)
| ID | 요구사항 | 근거 |
|---|---|---|
| FR-TRI-01 | 의도분류·RAG 결과를 근거로 SIMPLE_ANSWER / AUTO_ANSWER / NEED_MORE_INFO / HUMAN_REQUIRED 중 하나로 결정해야 한다(구조화 LLM 호출). | `triage_agent`, `TriageResult` |
| FR-TRI-02 | **명시적 상담사 연결 요청**(상담사/상담원, 또는 사람·직원 + 연결/바꿔)이 있으면 LLM 판단과 무관하게 **HUMAN_REQUIRED로 확정**해야 한다(결정성 보장). | `triage_agent` 오버라이드 |
| FR-TRI-03 | 앱/ARS에서 직접 처리 가능한 업무(분실·한도·결제일·재발급 등)는 상담사 요청이 없으면 AUTO_ANSWER로 강등해야 한다. | `triage_agent` 오버라이드 |
| FR-TRI-04 | 보이스피싱·사기·해킹·명의도용 등 긴급 키워드는 HUMAN_REQUIRED를 유지하고 긴급 플래그(`is_urgent_handover`)를 세팅, 동의·슬롯수집을 건너뛰어야 한다. | `triage_agent`, `answer_agent` |

### 3.4 자동응답 (RAG Answer)
| ID | 요구사항 | 근거 |
|---|---|---|
| FR-ANS-01 | AUTO_ANSWER는 검색된 근거 문서에 기반해 답변하고, 문서에 없는 내용은 추측하지 않아야 한다. | `answer_agent` AUTO_ANSWER |
| FR-ANS-02 | 답변은 TTS로 읽히므로 마크다운 기호 없이 구어체·간결(2문장 이내)로 생성해야 한다. | `answer_agent` 프롬프트 |
| FR-ANS-03 | 근거 문서가 없으면 상담사 문의 안내 메시지로 폴백해야 한다. | `answer_agent` |
| FR-ANS-04 | 응답에는 출처 문서(source/page/score) 메타데이터를 포함해야 한다. | `SourceDocument` |

### 3.5 지식검색 (RAG Retrieval)
| ID | 요구사항 | 근거 |
|---|---|---|
| FR-RAG-01 | Hybrid Search(벡터 0.6 + BM25 0.4, RRF k=30)로 검색하고, Cross-Encoder 리랭커로 재정렬해야 한다. | `vector_store`, `config` |
| FR-RAG-02 | 임베딩은 `jhgan/ko-sroberta-multitask`, 리랭커는 `Dongjin-kr/ko-reranker`, BM25 토크나이저는 Kiwi를 사용해야 한다. | `config` |
| FR-RAG-03 | 유사도 임계값(0.2) 미만이면 저신뢰로 처리하고, 상위 rerank 10개 중 최종 5개를 반환해야 한다. | `similarity_threshold`, `rerank_top_k/final_k` |
| FR-RAG-04 | "상담원 연결" 같은 메타 발화는 RAG 검색을 건너뛰어야 한다. | `vector_store` 메타쿼리 필터 |

### 3.6 정보수집 (Slot Filling / Waiting Agent)
| ID | 요구사항 | 근거 |
|---|---|---|
| FR-SLOT-01 | 카테고리별 필수/선택 슬롯 정의(9 도메인·57 슬롯)에 따라 미수집 슬롯을 한 턴에 하나씩 질문해야 한다. | `slot_definitions.json`, `slot_metadata.json`, `waiting_agent` |
| FR-SLOT-02 | **현재 질문 중인 슬롯의 답변은 현재 메시지에서 직접(focused) 추출**하여, 맨값(예: "0433")·날짜 답변이 누락되지 않아야 한다. | `waiting_agent._extract_answer_for_slot` |
| FR-SLOT-03 | 슬롯이 정상 캡처되면 어색한 재해석 없이 "감사합니다 + 다음 질문"으로 자연스럽게 이어가야 한다. | `waiting_agent` 전환 로직 |
| FR-SLOT-04 | "모르겠어요" 응답은 해당 슬롯을 '미확인'으로 저장하고 다음 슬롯으로 진행해야 한다. | `waiting_agent._check_unknown_response` |
| FR-SLOT-05 | 수집 중 고객이 이관 취소 의사를 보이면 핸드오버를 취소(`cancelled`)하고 일반 대화로 복귀해야 한다. | `waiting_agent._check_collection_cancel` |
| FR-SLOT-06 | 모든 필수 슬롯 수집 완료 시 `info_collection_complete=True`, `handover_status=pending`으로 전이해야 한다. | `waiting_agent` |

### 3.7 상담사 이관 (Handover)

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능/품질 KPI (목표값, `kpi_thresholds.py` 기준)
| 영역 | 지표 | 목표 |
|---|---|---|
| STT | CER / WER | ≤ 10% / ≤ 15% |
| STT | 금융용어 정확도 / TTFB | ≥ 95% / ≤ 300ms |
| 의도분류 | Intent Accuracy / Weighted F1 | ≥ 75% / ≥ 75% |
| 의도분류 | **HUMAN_REQUIRED Recall** / Top-3 Acc | ≥ 90% / ≥ 90% |
| Triage | Overall Accuracy | ≥ 85% |
| Triage | **HUMAN_REQUIRED 오검(FN) Rate** | ≤ 5% |
| RAG | Precision@3 / Recall@20 | ≥ 85% / ≥ 95% |
| RAG | MRR / NDCG@3 | ≥ 0.70 / ≥ 0.85 |

> **NFR-PERF-01**: 이관 미탐(HUMAN_REQUIRED FN)은 CX 리스크가 크므로 최우선 관리 대상이다. FR-TRI-02(결정적 오버라이드)가 이를 뒷받침한다.
> **NFR-PERF-02**: 음성 E2E(비스트리밍)는 STT+워크플로우+TTS 직렬 구조로 지연이 누적된다. 문장단위 스트리밍 TTS가 체감지연 핵심 레버다(`COST_ESTIMATION.md §7`). CPU-only 환경에서는 턴당 지연이 수십 초에 이를 수 있다.

### 4.2 보안·컴플라이언스
- **NFR-SEC-01**: LLM은 온프레미스(Ollama, qwen3.5:9b)로 운영 가능하여 데이터 외부 유출 없이 컴플라이언스를 만족한다(로컬 전환은 비용절감이 아닌 컴플라이언스 결정 — `COST_ESTIMATION.md`).
- **NFR-SEC-02**: 자격증명(API 키, DB 비밀번호)은 `.env`로만 로드하며 저장소에 커밋하지 않는다. `OPENAI_API_KEY`는 프로세스 env를 무시하고 `.env`에서만 로드한다(`config.py` 의도된 동작).
- **NFR-SEC-03**: 수집 슬롯(카드 뒤 4자리 등 개인정보)은 상담사 이관 목적에 한해 사용하고 세션 종료/취소 시 초기화한다.

### 4.3 가용성·확장성
- **NFR-AVL-01**: DB는 MySQL(운영) 또는 SQLite(로컬)로 구성 가능해야 하며 스키마는 기동 시 자동 생성된다.
- **NFR-SCA-01**: GPU 사이징은 decode 처리량이 결정하며 용량 산정은 `COST_ESTIMATION.md §5`를 따른다.
- **NFR-AVL-02**: `recent_reports` 캐시는 인메모리로, 백엔드 재시작 시 소실된다(개선 여지: DB 영속화 — `REQUIRED_IMPROVEMENTS.md`).

### 4.4 국제화·접근성
- **NFR-I18N-01**: 상담은 한국어 전용이며, 외국어/영어 입력은 정중히 한국어 사용을 안내한다.

| 시스템 | 용도 | 자격증명 |

## 7. 제약사항 및 가정
- **C-01**: 소형 로컬 LLM(qwen3.5:9b)은 tool-call 루프가 불안정하여 triage는 결정적 파이프라인(강제 intent→RAG→구조화 1콜)으로 구현한다(`triage_agent` docstring).
- **C-02**: qwen3.5는 thinking 모델로, `reasoning_effort="none"`로 사고과정을 비활성화해야 지연/토큰 폭증을 막는다.
- **C-03**: 턴수 분포·핸드오버율(30% 가정)·분주시율(17%)은 프로덕션 실측으로 확정 필요(`COST_ESTIMATION.md`).
- **C-04**: 벡터 유사도는 `1/(1+L2)` 공식을 사용한다(의도된 설계, `vector_store.py`).
